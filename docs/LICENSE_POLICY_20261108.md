# LICENSE 2.0：商業產品 QA 與對外服務邊界

**現行政策。** 2026-11-08後繼PM裁決正式允許個人、企業、開發者與組織，用AKC測試其合法開發、持有、經營或獲授權開發／修復／維護的商業及非商業產品。這是新政策，取代此前只限個人非商業用途的決定；不是說過去版本一開始就有這項權利。

完整條款以 [LICENSE 2.0](../LICENSE) 英文為準。本說明是PM政策對照與作者風險覆核，不是法院判決、法律意見認證或自動商業使用審批器。

## 目前允許什麼

商業產品收入、公司身分、QA公司身分、內部整合或內部改名，均不會單獨構成禁止理由。一般產品QA、企業內部QA與CI/CD、合法受託開發維護中的附帶驗證，以及不屬受限服務的一般安裝／設定／整合顧問工作，可依第2節使用。內部修改不必公開；產品原碼、資料、報告也不會因使用AKC而自動改受AKC授權。

保留兩類主要限制（第3節）：利用AKC／依法受保護衍生版本，向第三方提供獨立營利性QA測試／報告服務；或把其QA能力重新包裝、販售、以訂閱／API／廣告等營利性方式對外提供為QA工具、平台或託管服務。這些需相關權利人另行書面授權。

依實際交付、商業模式、受測系統權利及AKC角色合併判斷。不能只看另列QA費、AKC是不是主要工具、名稱是否保留，或用改名／拆帳作唯一判準。正常開發契約中的附帶QA不自動變成獨立QA服務；反過來，為QA商品附帶少量程式修改，也不自動取得開發例外。

| A05 | 合法受託開發／修復／維護產品，QA是實質附帶驗證 | 原則允許 | 第2／3節；不能只因契約有QA里程碑或費用項目就禁止 |

| R04 | 將AKC重新包裝成QA工具銷售 | 需另授權 | 第3(b)；把程式改名或加介面不迴避 |
| R05 | 對外提供AKC QA能力，以訂閱、API費或廣告營利 | 需另授權 | 第1／3(b)；未直接收「QA費」不是唯一豁免標準 |
| R06 | 整合進其他商品，實際仍販售受限QA服務／平台 | 需另授權 | 第3節；不能只靠AKC不是主要工具就排除限制 |
| G01 | 混合開發、維護、顧問及QA，未提供實際契約／交付內容 | 待釐清 | 可能為A05／A06或R01／R02；需主要交付、驗收與商業模式，沒有自設比例門檻 |
| G02 | 對客戶提供託管CI：可能只供一般運算，也可能販售AKC QA功能 | 待釐清 | 需客戶取得哪些功能、操作者角色及實際服務；不將所有CI主機商都視為QA平台 |
| G03 | 宣稱免費QA，但有贊助、廣告或其他收益安排 | 待釐清 | 若實質為受限營利QA供給適用第3節；不能單憑「免費」或「有收入」決定 |
| G04 | 付費非QA產品中含AKC：可能僅用於內部測試，也可能對客戶出售QA能力 | 待釐清 | A02／A04與R06均可能；須看使用與對外供給事實，不能籠統禁止所有付費整合 |

| G06 | 合法內部測試的既有報告，之後是否用於獨立營利QA業務不明 | 待釐清 | 報告本身不自動受AKC授權；另看是否正在利用Covered Material提供第3(a)服務，不主張永久控制所有生成內容 |

## 權利、資料與責任

第1／5節只涉及權利人實際控制、依法受保護的AKC材料與衍生內容。沒有宣稱可禁止獨立開發的相似概念、功能或商業模式；第三方授權、商標／名稱與Logo分開處理。權利來源核對及限度見 [NOTICE.md](../NOTICE.md)。

特定測試PASS、證據完整性MATCH、整體需求符合、正式驗收、獨立安全審計需要各自的證據。前兩項不自動證明後三項，也不證明不可偽造或已有第三方見證。企業使用許可不會改變沒有OS隔離、Windows僅父程序清理、模型可能外傳資料等既有邊界。
