# 2026-11-17 反向審查與有界修正

基線為本機／公開 main `72ede98cee177eed083a6f2fdf16c350596a7a61`，工作目錄乾淨、工具 preview.2、授權2.0。修正後工具為 preview.3，授權不變。審查涵蓋目標與風險選擇、計畫與正解、命令執行、收據重算、結果消費、缺陷分類及發布條件；不把內部未合格隔離 runner 當作此公開 profile。

## 確認問題與處置

### F01：必要自測意外跳過仍能發布成功

- **類型／優先級**：發布測具的成功條件缺陷，優先修正；不是受測產品漏洞，也不是偽造通過數。
- **適用與前提**：基線 `tools/validate_release.py` 的自測遺失、錯選或被非預期跳過。原本以實際 runner 計算結果，但只用 `wasSuccessful()` 決定自測成功。
- **可核反例**：在乾淨副本對 `WorkflowTests` 注入整類 `unittest.skip`，其餘原始執行與樣例不變；實際結果31個自測全跳過、0個通過，發布腳本仍返回0並輸出 `CI_RESULT_JSON`。五項樣例真的執行，不是自測的替代品。
- **影響**：必要防護未被執行，發布成功可能仍被沿用。不能據此否定之前確實31個實跑的Windows證據，或macOS／Linux30通過＋1個具名平台跳過。
- **修正／驗收**：`tests/required_cases.json` 獨立列必要案例身分與精確平台skip例外；發現集合、實跑集合、逐項成功／核准跳過都必須符合。少案、錯目標同數、零案、全跳過、單一非預期跳過的實際發布程序均被阻斷；單元負控另涵蓋重複、expected failure與提前停止。
- **剩餘限制**：這防止意外縮水，不證明每個測試的語意充分。能同時改程式、測試與契約的人仍可重定義它們；不能宣稱外部不可偽造。

### F02：verify摘要缺少已知的未驗證需求

- **類型／優先級**：確認的結果介面資訊缺漏與誤用風險，中優先；不是安全漏洞。
- **適用與前提**：只讀 `verify` JSON／退出碼的Agent或下游。基線計畫保留R01／R02，但只執行R01的一項行為檢查。
- **可核反例**：run為有效的局部PASS，result與報告正確列R02未配置／未驗證；verify返回PASS、MATCH、rc0，卻未帶回那些需求清單。文件已有局部範圍說明，因此不裁定這個PASS本身是錯誤產品驗收。
- **影響**：機器消費者必須額外開包才能取得已知缺口，容易將局部成功升格。根本未入計畫的重要需求，仍需由Agent按目標盤點，執行器不能自行發現。
- **修正／驗收**：run、report、verify分開呈現檢查判讀、已列需求狀態與三份需求清單；`goal_completion`明示未由runner裁定。保留原verdict與退出碼相容語意，不把局部PASS追溯改成FAIL。R02缺口、NOT_RUN、EXIT_MATCH、FAIL與INCONCLUSIVE有相應驗證。
- **相容性**：新結果schema3；舊preview.1 LF／CRLF與preview.2真實證據仍按原摘要／報告重算，僅在verify回傳補充覆蓋資訊。新工具拒絕舊計畫執行，要求重建，不改舊收據。

## 能依賴與仍未驗證

可依賴的是可信本機明列命令的有限判讀、原始收據、來源前後觀察、人口／報告重算、停止後續與拒絕同attempt重播，依其精確版本和案例成立。完整驗證與覆核狀態見 [ADVERSARIAL_VALIDATION.json](ADVERSARIAL_VALIDATION.json)；工具自測、五項樣例、發布負控、作者結果及跨客戶端覆核分列，不相加成產品成功率。

一次真實POSIX取消觀察到CANCELLED、後4項NOT_RUN、普通子程序已結束且包可核對。Windows僅父程序清理、脫離程序群組、強制殺掉工具／主機、部分副作用回滾，仍未由此證實。來源僅限明列檔案，未列依賴／動態還原／遠端環境仍有限；雲端Agent與子命令的資料流也不由本工具隔離。需要這些能力的任務不能宣稱已通過相應風險驗證，普通本機用途不因此全線停工。

## Gate與停止範圍

本輪Gate是「兩個確認問題的有界修正、同反例負控、既有防護回歸、歷史相容讀回與fresh覆核」，不是全面產品驗收、安全審計、Windows桌面回測或市場價值證明。fresh Claude覆核實際嘗試因既有OAuth過期且無法刷新而未執行，沒有取得模型覆核結果；作者自測不能代替工作區要求的fresh跨客戶端覆核。因此新版本以待覆核候選交付，main仍保留既有正式公開版本，不宣稱新候選已獲採用。候選發布、CI與讀回依實際准入及驗證資料記錄，規劃不算完成。

這些證據足以支持所述有限用途與修正決策後即收斂。其後只依具體問題選擇必要驗證；不要求新商業試點、朋友回測、推薦或自願回饋才算本輪完成。歷史失敗、舊授權與原生紀錄保留。
